# 共享元素仓库与合并管理

共享元素用于团队维护页面定位资源，主要内容为 XPath。开发者在 VS Code 编辑本机元素库并提交个人分支；OC 管理员审阅差异、处理冲突，再将申请合并到受保护的 `main`。Assistant 后台使用已批准的设备身份完成通信，Qt 窗口不承担元素编辑。

本功能提供仓库、分支、提交、差异、合并申请与历史恢复，数据保存在 SQLite 中，不依赖安装 Git，也不提供 Git remote、rebase、cherry-pick 或任意分支之间的合并。

## 先准备连接

1. 使用包含共享元素功能的 OC 与 Assistant。旧后台进程不会因替换源码或插件自动更新，应在现有任务完成后重启对应后台，或使用独立预览数据目录。
2. 在 Assistant 的连接设置中配置 OC 设备接入地址，由管理员批准绑定。跨电脑配置见 [OC 指南](oc.md)。
3. 安装 WBot Studio **0.6.0**，在本机可信 VS Code 工作区打开 WBot 元素库。
4. `wbot.libraryPath` 决定本次共享的本机库；每个库只关联一个当前工作副本。不同项目需要独立元素时，请为项目配置不同的绝对路径。该路径须与浏览器桥实际使用的库一致。
5. `wbot.assistantStateDir` 默认指向 `~/.wbot-assistant`。如果 Assistant 使用了其他 `--state-dir`，将这个设置指向相同目录；插件不用保存 OC 设备密钥。

共享操作通过 Assistant 后台运行，关闭其 Qt 窗口不影响通信。已安装旧版插件或便携包时，需要同时更新两端，避免旧后台缺少接口。

## 开发者操作

在 WBot 侧栏的“共享仓库”查看仓库、分支、审批状态与本地修改，点击变更元素打开单元素差异。标题栏的仓库图标按状态提供下一步操作，刷新图标重新读取状态。也可在命令面板执行 **WBot: 共享元素仓库**；详细 JSON 状态作为诊断入口保留。

| 操作 | 行为 |
| --- | --- |
| 连接共享元素仓库 / 创建分支 | 选择 OC 仓库，填写唯一的个人分支名称，以当前主分支作为基准 |
| 查看共享元素本地差异 | 使用 VS Code 只读差异编辑器比较最近提交与当前本机内容 |
| 提交共享元素版本 | 将当前元素快照提交到个人分支，需要填写提交说明，不改变主分支 |
| 发起元素合并申请 | 所有本机改动提交后，填写标题及验证说明，交由管理员处理 |
| 查看共享元素与合并状态 | 查看绑定、当前版本、本地变更、待确认操作与申请状态 |
| 拉取共享元素主分支 | 个人分支已合并且本机无未提交修改时，将共享主分支更新到本机库 |

首次连接保留本机已有元素，并补入主分支中本机缺少的元素。相同 ID 的本机内容作为待提交修改保留；不同 ID 的元素如果分组和名称相同，操作会停止，请先明确重命名或选择独立元素库。连接过程中发生的本机新增、编辑和删除不会被悄悄覆盖。

已有打开的合并申请会跟随后续分支提交更新；管理员必须重新审阅变化后的版本。申请被关闭后，可以继续修改、提交并新建申请。已经合并的分支不再接受提交，继续开发时创建新分支。

如果管理员合并后开发者已经继续编辑，可在**同一仓库**创建新分支，保留本机未提交改动。系统比较上次基准、最新主分支和本机内容；兼容修改带入新分支，字段冲突会指出元素 ID 和字段，要求对照最新主分支调整后重试。切换其他仓库仍需先处理未提交修改。

## 管理员操作

在 OC 左侧导航打开 **共享元素**。

[查看仓库界面](images/oc-shared-elements.png) · [查看合并审阅界面](images/oc-element-merge-review.png)。截图为实际界面和示例数据。

1. **创建仓库**：例如“ERP 页面元素”或“财务系统”。新仓库产生一个空主分支及创建记录。
2. **元素目录**：查看主分支的分组、名称、XPath、页面 URL、框架信息和描述；搜索定位需要维护的元素。
3. **分支与历史**：查看分支所属设备、基准和当前提交；查看历史完整快照。列表展示最近 100 条提交元数据。
4. **合并申请**：打开申请，比较新增、修改和删除。冲突需逐项选择保留主分支或申请版本，整条元素冲突允许选择删除。
5. **合并或关闭**：合并生成带两个父版本的新主分支提交；关闭需要填写原因。两种处理均保留申请记录。
6. **恢复历史版本**：选择历史快照并填写恢复说明，生成新的主分支提交；此前的提交与申请仍可追溯，不重写历史。

合并、关闭和恢复都校验管理员审阅时的版本。如果其他管理员推进了主分支，或开发者提交了新版本，旧操作会被拒绝，需要刷新并重新选择。不同 ID 的同分组同名元素不能同时写入主分支，开发者需先改名再提交，管理员不能凭一次合并静默替换另一个 ID。

## 合并规则

| 情况 | 处理 |
| --- | --- |
| 双方修改不同元素 | 自动组合 |
| 同一元素修改不同字段 | 自动组合，例如一方改 XPath，另一方改描述 |
| 双方把同一字段改为相同值 | 使用该值 |
| 双方把同一字段改为不同值 | 标为冲突，由管理员明确选择 |
| 一方删除、另一方修改同一元素 | 整条元素冲突，明确选择保留或删除 |
| 相同 ID 被双方分别新增且内容不同 | 整条元素冲突 |
| 不同 ID 合并后分组与名称重复 | 拒绝写入，要求开发者处理名称冲突 |

版本化字段为 `id`、`name`、`group`、`xpath`、`url`、`frame`、`description`；本机创建和修改时间不进入差异。XPath 使用现有元素定位校验，不能提交返回标量、属性或文本节点的定位表达式。单个快照最多 10,000 个元素、JSON 大小最多 1.5 MiB；HTTP 写入上限为 2 MiB。

## 数据保护、身份与当前边界

- 主分支只能通过管理端合并或恢复推进。开发者接口只能写当前设备拥有的个人分支、创建申请；待审批、拒绝或撤销的设备不能读写共享仓库。
- 当前所有批准设备均可读取默认组织的仓库和历史。作者记录是**设备 ID 与设备名称**，不是已验证的个人账号；成员角色、按仓库授权、多人会签仍待建设。
- 本机元素和共享基准在同一 SQLite 事务中更新。用户填写提交说明期间若发生新的改动，内容指纹校验会拒绝过期提交。远程提交期间的新修改仍留在本机，作为下一次未提交改动。
- 每次写入带稳定请求号。响应丢失后，查看状态会只读查询 OC 的已接受回执并恢复本机记录，不重新发出写请求；未被接受的操作可用原参数手动重试。提交、申请及合并的网络重试不会新增重复版本。
- 离线时保留本地元素和差异；提交、申请和拉取需要恢复已批准连接。切换 OC 不会把旧工作副本的修改发送到新服务器。
- 合并不会自动替换其他开发者的本机元素，也不会修改已构建的 `.wbot.zip`。自动化继续使用构建时导出的元素快照；新规则需要拉取、验证、重新构建并发布新版本。
- 仓库与工作副本不是凭据存储。URL、XPath、描述和框架信息会进入版本历史；业务凭据应留在相应运行配置中。

OC 的版本数据位于 OC 数据目录下 `elements.sqlite3`；本机工作副本元数据位于 `wbot.libraryPath` 数据库中的 `shared_element_state` 表。元素 JSON 导出只含元素记录，不包含绑定信息与请求回执。备份时在服务停止后一起保留 OC 数据目录和相应元素库。

## 开发验证

在仓库根目录使用已安装 wbot、lxml 的 Python：

```powershell
python -m unittest tests.test_oc_elements tests.test_shared_elements_http tests.test_assistant_shared_elements tests.test_element_workspace -v
npm --prefix oc-web test
npm --prefix oc-web run build
npm --prefix vscode-extension test
```

VS Code 测试可用 `WBOT_TEST_PYTHON` 指定实际 Python 路径。实现分别位于 [版本比较](../wbot/element_versions.py)、[OC 领域服务](../app/oc/element_service.py)、[Assistant 工作副本](../app/assistant/shared_elements.py) 与 [插件入口](../vscode-extension/src/shared-elements.js)。
